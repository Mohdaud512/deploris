Jeder KI-Agent-Einsatz, der in Produktion scheitert, scheitert auf eine von zwei Arten. Entweder sitzen Menschen überall im Loop (dann rechnet sich die Automatisierung nie), oder sie sitzen nirgendwo (dann skaliert die erste falsche Entscheidung sofort). Die Designfrage ist nicht, ob Sie Menschen in den Loop setzen. Sie ist, wo genau Sie sie setzen, und wie Sie die Zahl der Freigabestufen klein genug halten, damit der ROI überlebt.

## Die drei Tiers der Agenten-Aktionen

Ein Workflow hat kein einheitliches Risiko. Ein einzelner Rechnungsabgleichs-Agent kann aus zehn Systemen lesen, sechs Tools aufrufen und einen einzigen Schreibvorgang erzeugen, der Geld bewegt. Die Freigaben gehören an den Schreibvorgang, nicht an die Lesevorgänge. Jede Aktion, die der Agent ausführen kann, wird klassifiziert, bevor eine Zeile Code geschrieben wird.

### Tier 1: Vollautonom

Klassifikation, Routing, Anreicherung und reine Lese-API-Aufrufe. Der Agent führt diese Aktionen in voller Geschwindigkeit aus, protokolliert sie und fragt nie einen Menschen. Fehler sind billig, sichtbar und werden vom nächsten Schritt im Workflow korrigiert.

- Eine eingehende E-Mail als Reklamation, Verlängerung oder Rechnungsanfrage klassifizieren
- Einen CRM-Datensatz mit öffentlichen Firmendaten anreichern
- Eine Bestellung aus dem ERP zum Abgleich mit einer Rechnung lesen
- Ein Ticket inhaltlich einer Queue zuordnen

Kann eine Prüferin einen Monat später aus dem Log nachvollziehen, was passiert ist, reicht dieses Tier aus. Der Audit-Trail ist die Kontrolle, nicht eine Person im Moment.

### Tier 2: Nachgelagert auditiert

Interne Schreibvorgänge mit geringem Blast Radius, Kommunikation in internen Kanälen, Entwürfe, die ein Mensch versendet, und alles mit leichtem Rollback. Der Agent schreibt, das System protokolliert, und ein Mensch prüft eine Stichprobe wöchentlich oder monatlich.

- Eine interne Notiz an einem CRM-Datensatz anlegen
- Ein Status-Update in einen internen Slack-Kanal posten
- Einen Antwort-Entwurf vorbereiten, der in der Queue der Operator-Rolle landet, nicht im Posteingang der Kundin
- Einen Abgleichsvorgang innerhalb einer definierten Toleranz buchen

Nachgelagerter Audit funktioniert, wenn der Schreibvorgang begrenzt ist, das Rollback-Fenster weit genug, und die Stichprobe Drift auffängt, bevor er sich aufsummiert. Das 48-Stunden-Rückrollfenster auf jeden Schreibvorgang ist hier die strukturelle Absicherung, nicht ein Add-on.

### Tier 3: Menschliche Freigabe verpflichtend

Finanztransaktionen, externe Kommunikation, Datenlöschung, Rechtevergabe und alles, dessen Wirkung außerhalb des von Ihnen betriebenen Systems bestehen bleibt.

- Überweisungen, Zahlungen, Erstattungen oder jeder Schreibvorgang, der Geld bewegt
- Ausgehende E-Mail, SMS oder Chat an eine Kundin oder einen Lieferanten unter Ihrer Marke
- Hartes Löschen von Datensätzen in einem System of Record
- Zugriffsvergabe auf Systeme oder Daten
- Freigabe einer Änderung oberhalb eines definierten Betragsschwellenwerts

Diese laufen in keinem Vertrauenszustand unter keiner Shadow-Metrik unbeaufsichtigt. Verspricht ein Anbieter-Pitch „vollautonome KI-Mitarbeiter" für eine dieser Aktionen, verkauft er eine Haftung.

## Die Default-Klassifikationstabelle

Die Klassifikation steht im schriftlichen Scope, bevor jemand einen Editor öffnet. Wir schreiben sie als vierspaltige Tabelle (Aktion, Systeme, Tier, benannter Freigeber) und hängen sie an die Leistungsbeschreibung. Das Muster, das wir für die meisten Mittelstand-Mandate zu [KI-Automation für Operations](/de/use-cases/operations-ai-automation) nutzen, startet von einem Default und wird dann verengt.

| Aktionstyp | Default-Tier |
| --- | --- |
| Lesen aus einem internen System | Tier 1 |
| Klassifizieren, extrahieren, anreichern | Tier 1 |
| In eine Queue routen | Tier 1 |
| Schreiben einer internen Notiz oder eines Logs | Tier 2 |
| Interne Kommunikation (Slack, Teams) | Tier 2 |
| Abgleichs-Buchung innerhalb der Toleranz | Tier 2 |
| Abgleichs-Buchung oberhalb der Toleranz | Tier 3 |
| Entwurf an die Kundin (gehalten, nicht gesendet) | Tier 2 |
| Senden an die Kundin | Tier 3 |
| Finanz-Schreibvorgang (jeder Betrag) | Tier 3 |
| Löschen, Archivieren oder Rechteänderung | Tier 3 |

Die Defaults verschieben sich. Ein Abgleich gegen eine Sanktionsliste ist nicht Tier 1, sondern Tier 2 mit einem Menschen auf dem Treffer-Pfad. Eine Tier-2-Abgleichs-Buchung wird Tier 3, wenn der Lieferant neu ist. Der Punkt ist, von einer expliziten Tabelle zu starten und jede Abweichung schriftlich zu begründen, nicht zu improvisieren.

## Freigabe-Friktion hat Kosten

Die Versuchung beim ersten Einsatz ist, Freigaben überall zu setzen. Das ist prinzipiell sicherer. Es ist auch das Muster, das nach einem Quartal von der Leitung beendet wird, weil die Fachkräfte jetzt die Agent-Ausgabe prüfen, statt die ursprüngliche Arbeit zu erledigen. Drei Signale, dass Ihr Freigabe-Design mehr kostet, als es schützt:

- **Die Länge der Freigabe-Queue wächst schneller als die Automatisierungsrate.** Der Agent routet schneller an Menschen, als Menschen abarbeiten. Die Freigabestufe ist ein Nadelöhr, keine Absicherung.
- **Die Freigabequote liegt über 97 Prozent.** Winken Menschen fast alles durch, ist die Freigabe Theater. Entweder ist der Agent gut genug für diesen Schritt allein, oder die Menschen stempeln ab.
- **Fachkräfte lesen den Kontext nicht mehr.** Die Freigabestufe steht noch, die Klicks passieren, aber die Menschen vertrauen dem Agenten und werden schnell. Dieses Vertrauen ist angemessen, und es bedeutet, dass die Aufgabe der Freigabestufe in einen nachgelagerten Audit verschoben werden kann.

Praktisch bauen wir jede Freigabestufe mit einem Sunset. Jede Tier-3-Freigabestufe hat eine Bedingung, unter der sie auf Tier 2 fällt (Freigabequote über 95 Prozent für 60 Tage, innerhalb eines definierten Scopes). Jede Tier-2-Audit-Kadenz hat eine Bedingung, unter der sie auf Tier-1-Stichprobe fällt. Autonomie wird verdient; sie ist nicht gesetzt.

## Das Trust-Degrade-Muster

Das Gegenstück zur verdienten Autonomie ist der automatische Verlust. Macht der Agent einen Fehler (oder fängt eine Prüferin einen Fehler ab, den er gemacht hätte), muss sich das Freigabe-Design ohne Meeting verschärfen.

- Ein zurückgerollter Schreibvorgang im 48-Stunden-Fenster flaggt den betroffenen Schritt für ein Re-Review-Fenster von 14 Tagen
- Zwei zurückgerollte Schreibvorgänge in derselben Aktionsklasse schieben diese Aktion für 30 Tage von Tier 2 auf Tier 3
- Eine übersehene Ausnahme, die eine Eskalation verursacht hat, senkt den Konfidenzschwellenwert des gesamten Workflows um einen definierten Betrag und routet mehr Fälle an Menschen
- Jede Tier-3-Aktion mit einem menschlichen Override der Agent-Empfehlung fließt in den Kalibrierungsdatensatz und löst im nächsten zweiwöchigen Inkrement ein Prompt-Review aus

Nichts davon ist eine Ermessensentscheidung in einem Slack-Thread. Es steht in der Policy des Agenten und läuft gegen den Audit-Log. Der Punkt ist, dass die Autonomie des Systems atmet: Sie weitet sich, wenn die Metriken tragen; sie zieht sich zusammen, wenn nicht; und die Verengung hängt nicht davon ab, ob jemand aufpasst. Das 48-Stunden-Rückrollfenster auf jeden Schreibvorgang ist die strukturelle Absicherung, das mechanische Trust-Degrade die verhaltensbezogene.

## Wo Menschen tatsächlich hingehören, nach Workflow

Die obigen Muster sind generell. In der Praxis landen die Freigabestufen in jedem der am häufigsten gesehenen Workflows auf vorhersehbaren Aktionen.

### Rechnungsabgleich

Lesen aus ERP, Bestellsystem, Wareneingängen: Tier 1. Abgleichs-Buchung innerhalb der Toleranz: Tier 2 mit wöchentlicher Stichprobe. Abgleichs-Buchung oberhalb der Toleranz, neuer Lieferant oder Sanktionslisten-Treffer: Tier 3 mit benanntem Freigeber.

### Auftragsrouting

Klassifikation, Routing, Anreicherung: Tier 1. Interne Notiz am Auftrag: Tier 2. Änderung an Liefertermin, Preisstellung oder kundenseitigem Status: Tier 3.

### Support-Ticket-Vortriage

Klassifikation, Routing, Antwort-Entwurf: Tier 1 für alles außer dem Senden der Antwort. Senden an die Kundin: Tier 3, bis der Agent eine 60-Tage-Bilanz auf dieser Queue hat, danach Tier 2 mit Audit.

### Lieferanten-Onboarding

Dokumenten-Extraktion, Dateneingabe in interne Felder: Tier 2. Schreiben in den Lieferantenstamm, Freigabe für Zahlung oder Zugriffsvergabe: Tier 3.

Das Thema ist konsistent. Die Freigabestufe sitzt am Schreibvorgang, nicht am Lesen. Sie sitzt an der externen Wirkung, nicht am internen Reasoning. Sie sitzt am Unumkehrbaren, nicht am Rücknehmbaren.

## Nicht jeder Workflow ist agent-reif

Hat der Prozess keine aufgeschriebenen Regeln, keine messbare Ausnahmequote und keine benannten Systems of Record, ist die erste Aufgabe nicht, Menschen in den Loop zu setzen. Sie ist, den Prozess aufzuschreiben. Die Freigabestufen setzen einen Agenten voraus, der weiß, wie „korrekt" aussieht. Kann niemand sagen, wie „korrekt" aussieht, ist die Aufgabe der Freigabestufe undefiniert, und die Menschen bearbeiten den gesamten Fall ohnehin neu. Der Vergleich [KI-Agenten vs. Workflow-Automatisierung](/compare/ai-agents-vs-automation) deckt die Entscheidung zwischen deterministischem Pfad, Agent oder Mix ab, mit den Abwägungen für ein Mittelstand-Operations-Team.

Die Design-Arbeit ist ehrliche Arbeit. Eine Tabelle, eine Klassifikation pro Aktion, ein benannter Freigeber pro Tier-3-Freigabestufe, eine Trust-Degrade-Policy, ein 48-Stunden-Rückrollfenster und ein monatliches Review der Freigabemetriken. So gebaut, sind die Menschen im Loop diejenigen, deren Urteil tatsächlich tragend ist. Anders gebaut, sind die Menschen im Loop diejenigen, die früher den ganzen Fall gemacht haben und ihn jetzt beim Zuschauen immer noch zum größten Teil machen.
